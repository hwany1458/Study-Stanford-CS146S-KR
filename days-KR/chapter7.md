# 7장: 현대적 소프트웨어 지원

## 강의 개요

> "소프트웨어 코드 리뷰는 더 나은 엔지니어가 되기 위해 할 수 있는 가장 레버리지가 높은 활동 중 하나다"

코드 리뷰는 가장 레버리지가 높은 활동입니다. AI 코드 리뷰는 그 어느 때보다 중요합니다.

### 학습 목표
- 코드 리뷰의 중요성 이해
- 코드 리뷰 모범 사례 숙지
- AI 코드 리뷰 도구 사용법 학습
- AI 코드 리뷰의 한계 이해

---

## 1. 코드 리뷰 통계

| 지표 | 데이터 |
|------|--------|
| 코드 리뷰의 오류 발견율 | 55-60% |
| 코드 리뷰를 하지 않을 때의 오류율 | 100줄당 4.5개 |
| 코드 리뷰를 할 때의 오류율 | 100줄당 0.82개 |
| AT&T 사례 | 생산성 14% 향상, 결함 90% 감소 |
| 테스트 방식의 오류 발견율 | 25-45% |

**출처**: Coding Horror

---

## 2. 코드 리뷰에서 무엇을 확인할까?

### 로직과 정확성
- 코드 로직이 올바른가?
- 버그가 있는가?
- 엣지 케이스를 처리하는가?

### 가독성과 유지보수성
- 코드가 명확하고 읽기 쉬운가?
- 이름이 적절한가?
- 함수가 너무 길지 않은가?

### 성능
- 성능 문제가 있는가?
- 알고리즘이 최적인가?
- 불필요한 연산이 있는가?

### 보안
- 보안 취약점이 있는가?
- 입력 검증이 충분한가?
- 민감 데이터가 노출될 위험이 있는가?

### 모범 사례
- 프로젝트 관례를 따르는가?
- 언어/프레임워크의 모범 사례를 따르는가?
- 중복 코드가 있는가?

---

## 3. 좋은 코드 리뷰 vs 나쁜 리뷰

### 나쁜 리뷰
> "이건 안 될 거예요"

### 좋은 리뷰
> "새로 만든 메서드가 이 파일의 기존 스타일에 맞춰 [X]개의 파라미터를 받고 있네요. 파라미터가 이렇게 많으면 가독성이 떨어지고, 함수가 너무 많은 일을 한다는 신호이기도 합니다. 나중에 별도 풀 리퀘스트에서 이 메서드와 기존 메서드들을 리팩터링해서 파라미터 수를 줄이는 건 어떨까요?"

**출처**: Blake Smith

## 5. AI가 무엇을 바꾸었나?

| 측면 | 변화 |
|------|------|
| **효율성** | 대량의 코드를 빠르게 훑어 문제를 발견 |
| **일관성** | 모든 코드에 같은 기준을 적용 |
| **지식 공유** | 팀의 모범 사례를 확산 |
| **인지 부하 감소** | 일상적인 점검을 자동화 |
| **지속적 개선** | 시스템이 시간이 지나며 학습하고 개선 |
| **전체적 이해** | 코드베이스를 더 잘 이해 |

**출처**: Greptile, Graphite

---

## 6. AI 코드 리뷰의 한계

### 한계

| 한계 | 설명 |
|------|------|
| **추가 설정 필요** | 별도의 설정과 학습이 필요 |
| **오탐** | 시스템을 지속적으로 학습시켜야 함 |
| **관용구 파악 불가** | 저장소 고유의 관용구와 모범 사례는 아직 잡아내지 못함 |
| **복잡한 로직** | 복잡한 비즈니스 로직과 아키텍처 결정은 다루지 못함 |
| **보안 관련 변경** | 보안 관련 변경은 특히 신중해야 함 |
| **엣지 케이스** | 엣지 케이스를 자주 놓침 |

> **중요한 당부**: AI 시대에 코드 리뷰는 그 어느 때보다 중요합니다.
> 병합되고 배포되는 코드의 주인은 여러분입니다. AI 탓을 하지 마세요. AI는 조수이고, 최종 책임자는 여러분입니다.
